第五题：设计实验——同 builder 能离线，换 builder 为什么不行？

2 分钟阅读 · 第二轮五题自测：从记住结论到设计验证

原题

验证两个结论：同一套下载缓存里的包能在安装重跑时复用；换独立 builder，仅导入远端层缓存不能恢复这些下载包。

可使用 A、B 两套 builder、cache mount、参与安装步骤的新编号参数、联网/禁网及层缓存导入导出。基础镜像和解析器已准备好，安装脚本没有额外联网需求。不使用 --no-cache。

按顺序说明每一步用哪个 builder、是否联网、编号为何变化、预期 CACHED/执行成功/执行失败，以及结果证明什么。

我的反馈（原文）

没看懂这里要干啥

拆分解释

实验编号 ROUND 参与安装命令。换一个从未用过的编号，是为了让命令输入不同、避免整步 CACHED；它不负责选择下载缓存。

ARG ROUND
# 编号参与命令；挂载标识保持不变，供真正重跑的命令复用下载目录。
RUN --mount=type=cache,id=npm-downloads,target=/root/.npm \
    echo "本轮编号：$ROUND" \
    && npm ci --offline

先让 A 联网安装并填满所需下载包。然后问：仍用 A，换新 ROUND，禁止安装联网并执行 npm ci --offline，会怎样？

我的第一次回答（原文）

真正执行并成功，应为这里只是ci安装走的是离线

对应修正

选择正确，但不是“离线就成功”。新编号使安装真正重跑；同一 A 的下载挂载中所需包齐全，才使离线安装成功。缺包时离线模式会失败，不会自动补下载。

再问：A 导出了层缓存，新建独立 B 并导入；使用另一个新 ROUND，保持依赖不变、禁网离线安装，会怎样？

我的第二次回答（原文）

肯定是失败啊，因为它拿不到下载缓存并挂载到指定目录

对应修正

结论正确，但 B 不是“无法挂载目录”，而是能挂载它自己的一份空目录。相同 id 不会连接到 A 的存储。

完整实验预期：

步骤 builder / 安装网络 编号 预期 证明什么
1 A / 联网 全新编号 1 实际执行并成功，填充下载包；导出层缓存 建立实验输入
2 A / 禁网、离线 全新编号 2 实际执行并成功 同一存储的下载包可复用
3 全新 B / 导入远端层缓存，禁网、离线 全新编号 3 实际执行并因缺包失败 普通层缓存导入不恢复下载挂载

第 1、2 步可以使用同一份测试 Dockerfile，由网络模式和参数选择安装方式。表格是实验设计，不代表本轮已执行这些命令。

如果 B 不改 ROUND，可能直接命中已导出的安装结果而成功；那样没有执行 npm，不能用来证明 B 的下载目录中有包。
